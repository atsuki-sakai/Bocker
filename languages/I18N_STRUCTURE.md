# Bocker i18n 実装構造ドキュメント

## 概要
このドキュメントは、Bocker SaaSプロジェクトの多言語化(i18n)実装における翻訳ファイルの構造とルールを定義します。

## 翻訳ファイル構造

### ファイル配置
```
languages/
├── ja.json     # 日本語（デフォルト）
└── en.json     # 英語
```

### JSONファイル構造

翻訳キーは機能・画面単位でグループ化されています：

```json
{
  "feature": {          // 機能/画面名
    "section": {        // サブセクション（任意）
      "key": "value"    // 実際の翻訳文字列
    }
  }
}
```

- サブスクリプション関連メッセージ

### 5. dashboard - ダッシュボード
- ホーム画面の統計・グラフ関連
- 期間フィルター

### 6. reservationLink - 予約リンク管理
- トラッキング設定
- LINE連携メッセージ

- 紹介コード関連

- 一覧・タイムライン表示

- 基本アクション（保存、キャンセル等）

- ページネーション
- フィルター操作
- 成功/エラーメッセージ

## 命名規則

### キーの命名パターン

1. **画面タイトル**: `title`
2. **説明文**: `description`, `xxxDescription`
3. **ボタン**: `xxxButton` または動詞形（`save`, `cancel`）
4. **ラベル**: フィールド名をそのまま使用（`firstName`, `email`）
5. **プレースホルダー**: `xxxPlaceholder`
6. **メッセージ**: 
   - 成功: `xxxSuccess`
   - エラー: `xxxError`, `xxxFailed`
   - 確認: `confirmXxx`
7. **リスト関連**:
   - タイトル: `list`
   - 項目なし: `noXxx` (例: `noReservations`)
   - カウント: `xxxCount`

### 使用すべきでないパターン

1. 日本語をローマ字化したキー名
2. 過度に長いキー名（3階層まで）
3. 数字で始まるキー名

## 重複の管理

### 共通化すべきテキスト

以下のテキストは`common`セクションに配置：

- 基本的なUIアクション（保存、削除、編集等）
- ステータス表示（有効/無効、完了/未完了等）
- 汎用的なフォームフィールド（メールアドレス、名前等）
- エラー・成功メッセージのテンプレート

### 機能固有のテキスト

各機能セクションに配置すべきもの：

- 画面固有のタイトル・説明
- 業務用語（予約、顧客、メニュー等の詳細）
- 特殊なバリデーションメッセージ

## 実装ガイドライン

### コンポーネントでの使用

```typescript
import { useTranslations } from 'next-intl';

export function Component() {
  const t = useTranslations('feature');
  const tCommon = useTranslations('common');
  
  return (
    <div>
      <h1>{t('title')}</h1>
      <button>{tCommon('save')}</button>
    </div>
  );
}
```

### 動的な値の挿入

翻訳ファイル内でプレースホルダーは使用せず、コンポーネント側で結合：

```typescript
// 推奨
const message = `${t('earned')} ${amount} ${t('yen')}`;

// 非推奨（プレースホルダー使用）
// "earned": "獲得金額は {amount} 円です"
```

## メンテナンス

### 新規翻訳追加時のチェックリスト

1. [ ] 既存の`common`セクションに同じ/類似のテキストがないか確認
2. [ ] 適切なセクションに配置されているか確認
3. [ ] 命名規則に従っているか確認
4. [ ] 日本語・英語両方のファイルに追加されているか確認
5. [ ] 使用されていない翻訳キーがないか確認

### 定期的なレビュー
