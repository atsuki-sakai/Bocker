## 📋 概要
このドキュメントは、ConvexからSupabaseへの予約履歴データ移行に関するテスト計画を記載します。

## 🎯 テスト目標
1. データの完全性を保証する
2. パフォーマンス目標を達成する（10,000件/分以上）
3. エラー率を0.1%以下に抑える
4. ダウンタイムゼロで移行を実施する

## 🔍 検証項目

### データ整合性
1. **レコード数の一致**
   ```sql
   -- Convex側の確認
   convex.reservation.count()
   
   -- Supabase側の確認
   SELECT COUNT(*) FROM reservation WHERE _convex_id IS NOT NULL;
   ```

2. **データ内容の一致**
   - master_id, tenant_id, org_idの完全一致
   - 日時データの正確性
   - JSON型データの構造保持
   - 文字化けの有無

3. **リレーションの整合性**
   - reservation → reservation_detailの関連
   - _convex_idの一意性
   - _convex_reservation_idの参照整合性

### パフォーマンス指標
1. **処理速度**
   - 目標: 10,000件/分以上
   - 計測: バッチごとの処理時間

2. **リソース使用量**
   - CPU使用率: 50%以下
   - メモリ使用量: 1GB以下
   - データベース接続数: 20以下

3. **エラー率**
   - 目標: 0.1%以下
   - リトライ成功率: 99%以上

## 🚨 エラー対応

### エラーレベル定義
1. **Critical（即時対応）**
   - データ損失の可能性
   - システム全体の停止
   - セキュリティ違反

2. **Warning（監視強化）**
   - パフォーマンス劣化
   - エラー率上昇
   - リソース逼迫

3. **Info（記録のみ）**
   - 個別レコードのリトライ
   - 一時的な遅延
   - 予期された例外

### 対応手順
1. **即時対応**
   - 処理の一時停止
   - エラーログの確認
   - 原因の特定
   - 修正または回避策の実施

2. **事後対応**
   - 失敗レコードの再処理
   - データ整合性の確認
   - 再発防止策の検討
