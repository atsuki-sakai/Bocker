## 📊 関数呼び出し回数に基づく詳細コスト分析【実測値反映版】

### 実際の予約処理で発生するConvex Function Call回数

#### 1回の予約作成処理での詳細分析

**フロントエンド画面表示時:**
- 初期データ取得: 5回（組織設定、メニュー一覧、オプション一覧、スケジュール、例外スケジュール）
- ユーザー操作による動的取得: 3回（利用可能スタッフ、スタッフスケジュール、予約時間計算）

**予約時間計算（calculateReservationTime）内部処理:**
- 内部function call: 5回（利用可能時間、スタッフスケジュール×2、組織設定再取得、スタッフ予約状況）

**予約作成実行時:**
- メイン処理: 7回（スタッフ確認、組織確認、予約設定取得、重複チェック×2、予約作成×2）

**合計: 1回の予約作成で20回のConvex Function Call**

#### Webhook処理でのConvex Function Call回数

**Stripe Subscription Webhooks:**
- customer.subscription.updated: 3回
- customer.subscription.deleted: 4回
- invoice.payment_succeeded: 4-5回（初回時リファラルボーナス含む）
- invoice.payment_failed: 3回

**Stripe Connect Webhooks:**
- account.updated: 3回
- account.external_account.deleted: 3回
- capability.updated: 3回

**Clerk User Events:**
- user.created: 12-13回（新規テナント作成時）
- user.updated: 4-6回
- user.deleted: 4回

**1店舗あたりの月間Webhook処理想定:**
- Stripe関連: 平均8回/月（決済・設定変更）
- Clerk関連: 平均2回/月（スタッフ管理）
- 合計: 10回/月 × 平均4 function calls = 40回/月/店
