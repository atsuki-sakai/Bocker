# 予約作成・キャンセル機能 テスト計画書

作成日: 2025年1月

## 1. テスト概要

本テスト計画書は、予約作成・キャンセル機能が仕様書通りに実装されているかを検証するための包括的なテストケースを定義します。

## 2. テスト環境

### 2.1 必要な環境
- 開発環境（localhost）
- Convex開発インスタンス
- Supabase開発インスタンス
- Stripe Test Mode
- テスト用メールアドレス
- テスト用LINE ID（LIFF環境）

### 2.2 テストデータ
- テスト用組織（org_id）
- テスト用スタッフ（複数）
- テスト用顧客アカウント（複数）
- テスト用メニュー・オプション
- Stripeテストカード番号

## 3. 予約作成機能テストケース

### 3.1 基本的な予約作成

#### TC-001: 現金決済での予約作成（顧客向けページ）
**前提条件**:
- 顧客がログイン済み
- 利用可能なスタッフ・時間帯が存在

**手順**:
1. 予約ページ（/reservation/[id]/calendar/）にアクセス
2. メニューを選択（例：カット ¥5,000）
3. スタッフを選択
4. オプションを選択（例：トリートメント ¥2,000）
5. 日時を選択（明日の14:00）
6. 支払方法で「現金」を選択
7. 予約確定ボタンをクリック

**期待結果**:
- [ ] 予約がstatus='confirmed'で作成される
- [ ] payment_status='pending'で作成される
- [ ] 予約確認メールが送信される
- [ ] LINE通知が送信される（LINE ID登録済みの場合）
- [ ] オプションの在庫が減る（in_stock: 10 → 9）

#### TC-002: クレジットカード決済での予約作成
**前提条件**: TC-001と同じ

**手順**:
1. 手順1-5はTC-001と同じ
2. 支払方法で「クレジットカード」を選択
3. 予約確定ボタンをクリック
4. Stripeの決済画面で以下を入力：
   - カード番号: 4242 4242 4242 4242
   - 有効期限: 任意の未来日付
   - CVC: 任意の3桁
5. 決済を完了

**期待結果**:
- [ ] 予約がstatus='pending'で作成される
- [ ] Stripe Checkout Sessionが作成される
- [ ] 決済完了後、Webhookでstatus='confirmed'に更新される
- [ ] payment_status='paid'に更新される
- [ ] 予約確認メールが送信される
- [ ] 30日後のポイント付与タスクが作成される

#### TC-003: ポイント使用を含む予約作成
**前提条件**:
- 顧客が500ポイント保有
- その他はTC-001と同じ

**手順**:
1. 手順1-5はTC-001と同じ
2. ポイント使用で300ポイントを入力
3. 支払方法で「現金」を選択
4. 予約確定ボタンをクリック

**期待結果**:
- [ ] 合計金額が¥7,000から¥6,700に割引される
- [ ] 顧客のポイント残高が500→200に減る
- [ ] point_transactionに-300ポイントの記録が作成される
- [ ] 予約詳細のuse_pointsに300が記録される

#### TC-004: クーポン使用を含む予約作成
**前提条件**:
- 有効な10%割引クーポンが存在
- その他はTC-001と同じ

**手順**:
1. 手順1-5はTC-001と同じ
2. クーポンコードを入力
3. 支払方法で「現金」を選択
4. 予約確定ボタンをクリック

**期待結果**:
- [ ] 合計金額が¥7,000から¥6,300に割引される
- [ ] 予約詳細のcoupon_idとcoupon_discountが記録される
- [ ] クーポンの使用回数が増加する

### 3.2 管理画面からの予約作成

#### TC-005: 既存顧客の予約作成（スタッフ操作）
**前提条件**:
- スタッフが管理画面にログイン済み
- 既存顧客が存在

**手順**:
1. 管理画面の予約追加ページ（/dashboard/reservation/add/）にアクセス
2. 顧客検索で「田中」と入力
3. 検索結果から顧客を選択
4. メニュー・スタッフ・日時を選択
5. 予約作成ボタンをクリック

**期待結果**:
- [ ] 予約がstatus='confirmed'で作成される（現金決済のみ）
- [ ] 顧客のlast_reservation_date_unixが更新される
- [ ] total_reservation_countが1増加する
- [ ] カルテが自動作成される（初回の場合）

#### TC-006: 新規顧客の予約作成（スタッフ操作）
**前提条件**: TC-005と同じ

**手順**:
1. 管理画面の予約追加ページにアクセス
2. 「新規顧客」を選択
3. 顧客情報を入力（名前、電話番号、メール）
4. メニュー・スタッフ・日時を選択
5. 予約作成ボタンをクリック

**期待結果**:
- [ ] 新規顧客がSupabaseに作成される
- [ ] 予約が作成される
- [ ] カルテが自動作成される

**期待結果**:

**期待結果**:

## 4. 予約キャンセル機能テストケース

### 4.1 正常系キャンセル

#### TC-011: 期限内の顧客自身によるキャンセル
**前提条件**:
- 3日後の予約が存在
- available_cancel_days=1に設定

**手順**:
1. 顧客が予約詳細ページにアクセス
2. キャンセルボタンをクリック
3. 確認ダイアログで「はい」を選択

**期待結果**:
- [ ] 予約のstatus='cancelled'に更新される
- [ ] cancelled_at, cancelled_by='customer'が記録される
- [ ] キャンセル確認メールが送信される
- [ ] LINE通知が送信される（LINE ID登録済みの場合）

#### TC-012: ポイント使用予約のキャンセル
**前提条件**:
- 300ポイントを使用した予約が存在
- 現在のポイント残高が200

**手順**:
1. TC-011と同じ手順でキャンセル

**期待結果**:
- [ ] 使用した300ポイントが返還される（残高: 200→500）
- [ ] point_transactionに+300ポイントの記録（type='refund'）
- [ ] 予定されていたポイント付与タスクがstatus='cancelled'になる

#### TC-013: クレジットカード決済予約のキャンセル
**前提条件**:
- クレジットカードで支払済みの予約が存在

**手順**:
1. TC-011と同じ手順でキャンセル

**期待結果**:
- [ ] Stripe返金APIが呼び出される
- [ ] 返金処理が開始される
- [ ] メール通知に「返金処理を行います」の文言が含まれる

#### TC-014: オプション付き予約のキャンセル（在庫復元）
**前提条件**:
- オプション（在庫管理あり）を含む予約が存在
- 現在の在庫: 9

**手順**:
1. TC-011と同じ手順でキャンセル

**期待結果**:
- [ ] オプションの在庫が復元される（9→10）
- [ ] 複数オプションの場合、すべて復元される

#### TC-015: スタッフによる期限切れキャンセル
**前提条件**:
- 明日の予約が存在
- available_cancel_days=2に設定（期限切れ）

**手順**:
1. スタッフが管理画面から予約詳細にアクセス
2. キャンセルボタンをクリック
3. 期限切れ警告が表示される
4. 「続行」を選択
5. キャンセル理由を入力

**期待結果**:
- [ ] 期限を無視してキャンセルが成功する
- [ ] cancelled_by='staff'が記録される
- [ ] cancel_reasonが記録される

## 5. 統合テスト

### 5.1 エンドツーエンドシナリオ

#### TC-020: 予約作成から完了までの一連フロー
**シナリオ**:
1. 顧客が新規予約を作成（ポイント使用、クレジットカード決済）
2. 予約確認メール・LINE通知を確認
3. 予約日前日に来店リマインダーを確認（実装されている場合）
4. 来店・施術完了
5. 30日後にポイントが付与される

**検証項目**:
- [ ] 各ステップでデータの整合性が保たれる
- [ ] ポイントの増減が正確
- [ ] 通知が適切なタイミングで送信される

#### TC-021: 複数予約の同時処理
**シナリオ**:
1. 3人の顧客が同時に同じ時間帯で予約を試みる
2. 1人目と2人目は成功、3人目は上限エラー

**検証項目**:
- [ ] レースコンディションが発生しない
- [ ] 正確に上限数で制限される
- [ ] エラーが適切に表示される

### 5.2 ストレステスト

#### TC-022: 大量同時アクセス
**シナリオ**:
- 100件の予約作成を同時実行
- 様々な時間帯、スタッフ、メニューの組み合わせ

**検証項目**:
- [ ] システムがクラッシュしない
- [ ] レスポンスタイムが許容範囲内（3秒以内）
- [ ] データの不整合が発生しない

#### TC-023: Webhook重複処理
**シナリオ**:
- 同じStripe Webhookイベントを複数回送信

**検証項目**:
- [ ] べき等性が保たれる（重複処理されない）
- [ ] エラーが発生しない
