# Cloudflare R2画像移行設計

## 目的

壊れているGCP Cloud CDN配信をCloudflare R2へ置き換え、既存URL
`https://cdn.bocker.jp/<object-key>` の形式を維持する。Convexの画像URLスキーマと既存行は変更しない。

## 構成

- 画像メタデータ: Convexを継続利用
- 画像本体: `bocker-images` R2バケット
- 公開配信: R2 custom domain `cdn.bocker.jp`
- ブラウザアップロード: 認証済みNext.js APIが発行する期限付きPUT URL
- サーバーアップロード・削除: R2 S3互換APIの期限付きURLを内部利用

既存の画像圧縮、ファイル名、`menu/original/<orgId>/...` などのキー規則は維持する。
R2用の認証情報はサーバー環境変数だけに置き、クライアントへは期限付きURL以外を返さない。

## 既存画像の扱い

GCPの請求を再有効化せず、GCSオブジェクトの読み出し・R2へのコピーは行わない。
既存のConvex画像URLは残すが、対応する画像本体はR2に存在しないため、必要な画像は管理画面から再アップロードする。
再アップロード後の画像と新規画像だけをR2から配信する。

## 移行手順

1. Cloudflare FreeゾーンとR2バケットを作成する。ネームサーバーはこの時点で変更しない。
2. 現行DNSレコードを検出・比較し、メール関連レコードを含めてCloudflareへ複製する。
3. GCSの読み出し・コピーを行わないことを切替条件として確認する。
4. VercelとConvexへR2環境変数を設定する。この時点では新しいアプリコードをデプロイしない。
5. 短い画像更新メンテナンスを開始し、画像の新規アップロード・削除を止める。
6. Cloudflareゾーンを有効化し、`cdn.bocker.jp` をR2 custom domainへ接続する。R2へ置いた確認用オブジェクトがHTTP 200で取得できることを確認する。
7. R2へ書き込むアプリとConvex関数を続けてデプロイし、サーバー経由・期限付きURL経由の両アップロードを確認する。
8. 新規画像が`cdn.bocker.jp`で取得できることを確認してメンテナンスを終了し、実画面表示を確認する。
9. GCS側は読み出し・変更・削除を行わず、そのまま残す。

## 安全策

- DNS切替前に既存9レコードを比較する。
- GCP請求を再有効化せず、既存GCSオブジェクトを読み出し・上書き・削除しない。
- R2認証情報はログ、Git、ブラウザレスポンスに出さない。
- 署名付きURLはオブジェクトキーとContent-Typeを固定し、30分で失効させる。
- custom domain切替からR2書き込みコードのデプロイ完了までは画像更新を受け付けない。
